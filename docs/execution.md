# 行情与交易执行

[English](execution.en.md) | [简体中文](execution.md)

[项目首页](../README.zh-CN.md)

交易程序根据最新行情计算目标仓位，与账户实际持仓比较后，按差额生成调仓订单。

![交易流程](../assets/execution-cn.png)

## 行情更新

行情通过 OKX API 获取，包括永续合约 K 线和资金费率，下载后存到本地。不同合约可以并行更新，请求失败时会重试。

策略每小时运行一次。先检查数据是否更新，再计算因子；如果更新步骤返回失败，就跳过这一轮交易。

## 目标仓位与账户对账

各因子独立生成仓位，再等权合成组合目标。程序读取账户余额和已有持仓，结合价格、杠杆和合约面值，将目标仓位换算为合约数量。

目标数量减去已有持仓，就是需要调整的数量。下单前还会检查价格、合约规格和最小交易数量。

## 订单处理

| 环节 | 实现方式 |
|---|---|
| 获取报价 | 查询盘口，根据买卖方向确定限价 |
| 提交订单 | 提交限价单并指定持仓方向 |
| 查询状态 | 轮询成交进度 |
| 更新报价 | 价格变化时撤单重挂 |
| 超时处理 | 结束等待并处理未成交部分 |
| 执行记录 | 保存订单结果和执行时间 |
| 账户监控 | 定时查询余额与持仓，发送通知 |

不同合约的调仓任务由线程池处理。策略在每小时整点触发，账户监控在每小时第 5 和第 35 分钟运行。限价追踪循环上限为 210 秒，轮询间隔约 1.5 秒；网络请求和重试可能延长总耗时。

## 交易成本与执行研究

我在回测中使用万分之 2.5 的费率，实盘平均成交费率约为万分之 3.8。后续研究中，我希望把这部分成本差异与具体的下单方式联系起来。

| 费用项目 | 费率 |
|---|---:|
| 回测交易费率 | 0.025%（万分之 2.5） |
| 实盘吃单费率 | 0.050%（万分之 5） |
| 实盘挂单费率 | 0.020%（万分之 2） |
| 实盘平均成交费率 | 约 0.038%（万分之 3.8） |

实盘费率对应我的账户及上述运行期间；已有回测结果仍按万分之 2.5 计算。

具体会考虑挂单价格、等待时间和撤单重挂频率。挂单费用较低，但等待过久或未能成交会耽误调仓，因此需要同时比较手续费、滑点、成交率和执行耗时。

后续还会继续研究订单簿以及挂单策略，这是下一步深入的研究方向。

账户收益与停止运行的记录见[实盘记录](https://github.com/Chattan258/Crypto-Tradingsystem/blob/main/docs/live-trading.md)。
